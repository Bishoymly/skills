PR #218 - Persist order cancellations with an audit record

Record who cancelled an order, why, and when. Store cancellation details separately from the order, and add a timestamp to support cancellation checks without joining the audit table.

Database

order_cancellations

Columns in the new order_cancellations table
ColumnTypeNULL / defaultNotes
iduuidNOT NULL · newid()Primary key
order_iduuidNOT NULLReferences orders.id
cancelled_byuuidNOT NULLReferences users.id
reasontextNULL
cancelled_attimestamptzNOT NULL
Foreign keys
order_id → orders.id; cancelled_by → users.id. Both use ON DELETE RESTRICT to retain audit references.

orders

Column added to the existing orders table
ColumnTypeNULL / defaultNotes
cancelled_attimestamptzNULLNULL until cancelled; matches the audit record timestamp.
Migration
Create order_cancellations, then add orders.cancelled_at. No additional index on orders.
Consistency
The application locks the order row and writes both timestamps in one transaction; foreign keys alone do not enforce their equality.

API

Added, modified, and removed API endpoints
ChangeMethodEndpointDescription
POST/orders/{order_id}/cancellationsCancel an order and create its audit record. Accepts an optional reason; returns 201 with cancellation details.
GET/orders/{order_id}Response now includes nullable cancelled_at. Returns 200; other order fields are unchanged.
POST/orders/{order_id}/cancelLegacy cancellation endpoint removed. Clients must use POST /orders/{order_id}/cancellations to retain an audit record.

State machine

stateDiagram-v2
    direction LR
    state "Active order" as Active
    state "Processing cancellation" as Processing
    state "Cancelled order" as Cancelled
    Active --> Processing: Submit cancellation
    Processing --> Active: Validation fails or transaction rolls back
    Processing --> Cancelled: Audit record and timestamp committed
Processing
Transient request state, not a stored order status. The order remains active until the transaction commits.
Cancelled
cancelled_at is set and the audit record exists. Duplicate cancellation requests are rejected; no reversal is introduced.
